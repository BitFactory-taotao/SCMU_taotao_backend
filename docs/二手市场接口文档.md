## 接入约定

| 项目 | 约定 |
| --- | --- |
| HTTP 基路径 | `/api/v1/campus-taotao`。接口路径相对于此基路径，使用部署环境的服务地址。 |
| 鉴权 | 标为 `Token` 的入口传 `Authorization: Bearer <token>`，也支持纯 Token。学生端使用学生登录凭证。标为匿名的接口可直接请求。 |
| 凭证有效期 | Token 由 Redis 管理，有效期 2 小时。校验成功会续期。 |
| 请求体 | 有 JSON 请求体时使用 `Content-Type: application/json`。图片上传使用 `multipart/form-data`。 |
| 参数位置 | `Path` 是路径占位符，`Query` 拼接在 URL 上，JSON 字段放在请求体。 |
| 业务类型 | `int32` 和 `int64` 为相应宽度的整数，`number` 为 JSON 数值，`boolean` 为 `true` 或 `false`，`[]` 表示数组。 |

### HTTP 响应结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `int32` | 业务码，`200` 表示成功。 |
| `msg` | `string` | 业务提示或失败原因。 |
| `data` | 按接口定义 | 成功的业务数据。值为空时可能省略。 |
| `total` | `int64` | 使用顶层总数分页时的总记录数。 |

鉴权失败由拦截器返回 HTTP `401` 和业务 `401`。Controller 或全局异常处理器返回 `Result` 时，HTTP 状态通常为 `200`，前端需检查业务 `code`。已识别的参数绑定和校验错误通常返回业务 `400`，其他错误按各接口说明处理。JSON 全局采用 `non_null` 配置。

### 无数据响应

```json
{
  "code": 200,
  "msg": "操作成功"
}
```

### 分页对象响应

`data.total` 为总记录数（`int64`），`data.pages` 为总页数（`int64`），`data.list` 为当前页数组。每个列表项的结构在对应接口中链接。

```json
{
  "code": 200,
  "msg": "请求成功",
  "data": {
    "total": 0,
    "pages": 0,
    "list": []
  }
}
```

## 分页请求参数

分页参数都放在 Query 中，类型为 `int32`。页码和每页条数均可省略，默认值分别为 `1` 和 `10`。各入口通过下表规则区分校验与回退行为。

| 规则 | 参数 | 页码 | 每页条数 |
| --- | --- | --- | --- |
| 首页分页 | `page`、`size` | 小于 1 的值回退到 1。 | 小于 1 回退到 10，大于 50 按 50 处理。 |
| 每页最多 50 条 | `page`、`size` | 大于等于 1。 | 取值 1 到 50。 |
| 正整数分页 | `page`、`size` | 大于等于 1。 | 大于等于 1。 |
| 基础分页 | `page`、`size` | 绑定整数。 | 绑定整数，接口未定义统一上限。 |
| 预购分页 | `page`、`size` | 小于 1 的值回退到 1。 | 超出 1 到 100 时回退到 10。 |
| 黑名单分页 | `page`、`size` | 大于等于 1。 | 取值 1 到 100。 |

### 首页商品列表

`GET /goods` · 学生端 · 匿名可带 Token

**请求**

| 位置 | 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| Query | `tab` | `string` | 选填 | `recommend` | 标签取 recommend、dormitory、entertainment、study、pre-order。优先于 category。 两者都不填时使用 recommend。 |
| Query | `category` | `string` | 选填 | — | tab 为空时的兼容参数，值域与 tab 相同。 |

返回[分页对象响应](#分页对象响应)。`data.list` 元素为 [商品摘要](#商品摘要)。

**行为与错误**

`dormitory`、`entertainment`、`study` 分别对应宿舍用品、娱乐用品、学习用品。`pre-order` 查在线预购。`recommend` 采用用户偏好或冷启动热门结果，并组装同一商品摘要。标签非法用业务 `400`。

`POST /file/upload/images` · 学生端 · Token

**请求**

使用 `multipart/form-data`。

| 位置 | 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `imageUrls` | `string[]` | 必填 | 非空地址数组。服务端按原始地址去重处理。 |

**响应**

| 字段 | 类型 | 返回条件 | 说明 |
| --- | --- | --- | --- |
| `deleted` | `string[]` | 总是 | 成功删除的地址。 |

**行为与错误**

去重后处理。仅处理当前用户目录内、未被商品图片记录引用的图片。部分成功时 `code=200`。全部失败时 `code=400`，无结果明细。

### WebSocket 握手

| 项目 | 值 |
| --- | --- |
| SockJS 入口 | `/api/v1/campus-taotao/ws/messages`，使用部署环境的服务地址。 |
| 鉴权 | 握手优先使用 HTTP `Authorization`。浏览器无法传握手头时可以通过 Query `token` 传入登录凭证。 |
| 会话身份 | 发送者来自服务端握手身份。每次发送的 `receiverId` 须与会话中的对方用户一致。 |

### STOMP 目的地索引

| 方向 | 目的地 | 消息 |
| --- | --- | --- |
| 发送 | `/app/messages/send` | [通过 STOMP 发送文本](#通过-stomp-发送文本) |
| 发送 | `/app/messages/send/media` | [通过 STOMP 发送媒体](#通过-stomp-发送媒体) |
| 订阅 | `/user/queue/messages` | [STOMP 消息与确认数据](#stomp-消息与确认数据) 或 [STOMP 系统通知](#stomp-系统通知)。 |
| 订阅 | `/user/queue/messages/ack` | [STOMP 消息与确认数据](#stomp-消息与确认数据)。用顶层 `id` 对齐已保存的消息。 |
| 订阅 | `/user/queue/errors` | [HTTP 响应结构](#http-响应结构)形状，异常消息为业务 `500`。 |

### 通过 STOMP 发送文本

`SEND /app/messages/send` · 学生端实时消息

**消息体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `chatId` | `int64` | 必填 | 会话 ID。 |
| `receiverId` | `string` | 必填 | 会话对方用户 ID，须非空白。 |
| `content` | `string` | 必填 | 非空白正文，最多 1000 字符。 |

```json
{
  "chatId": 101,
  "receiverId": "student-b",
  "content": "请问这件商品还在吗？"
}
```

**响应**

成功时通过 `/user/queue/messages/ack` 返回 [STOMP 消息与确认数据](#stomp-消息与确认数据)。消息同时投递给接收方。发送异常推到 `/user/queue/errors`。

### 通过 STOMP 发送媒体

`SEND /app/messages/send/media` · 学生端实时消息

**消息体**

包含 [媒体消息请求](#媒体消息请求) 的全部字段，并附加下列字段。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `chatId` | `int64` | 必填 | 会话 ID。 |
| `receiverId` | `string` | 必填 | 会话对方用户 ID，须非空白。 |

**响应**

成功确认、错误目的地和接收方推送与 [通过 STOMP 发送文本](#通过-stomp-发送文本)一致。

消息保存后，HTTP 和 STOMP 发送均会在事务提交后推送。HTTP 发送更新会话摘要，STOMP 发送保留原摘要。历史消息的已读字段为 `isRead`，STOMP 消息为 `read`。已读操作使用 [标记会话已读](#标记会话已读)。

实现见 [WebSocketConfig](../src/main/java/com/bit/scmu_taotao/config/WebSocketConfig.java)、[握手拦截器](../src/main/java/com/bit/scmu_taotao/interceptor/WebSocketAuthHandshakeInterceptor.java) 和 [MessagesController](../src/main/java/com/bit/scmu_taotao/controller/MessagesController.java)。

### 手动刷新热门推荐缓存

`POST /goods/cache/refresh-hot` · 后端运维 · Token

**请求**

无业务参数。

**响应**

成功时 `data` 为对象，字段如下。

| 字段 | 类型 | 返回条件 | 说明 |
| --- | --- | --- | --- |
| `refreshTime` | `string` | 总是 | 本次请求的处理时间，格式 yyyy-MM-dd HH:mm:ss。 |

**行为与错误**

触发热门缓存刷新。Controller 的管理员校验仍为 TODO，当前拦截器接受已登录 Token。底层刷新异常会记录日志，缓存结果可通过推荐监控或服务日志核实。

### 查看推荐系统监控

`GET /goods/statistics` · 后端监控 · Token

**请求**

无业务参数。

**响应**

成功时 `data` 为 [推荐监控数据](#推荐监控数据)。

**行为与错误**

读取浏览记录与热门缓存状态。Service 统计异常时可以返回业务成功并设置 `data.status=error`，Controller 捕获到异常时返回 `500`。
