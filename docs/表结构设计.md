# 校园淘淘数据库表结构

## 阅读与联调

- 18 张表均使用 `InnoDB` 和 `utf8mb4`。每表列出排序规则、主键和次级索引。索引未标注 `DESC` 时使用升序。
- 物理约束共 59 个索引（含 18 个主键）和 14 个外键。外键动作逐项列出，应用按 ID 查询形成的关联见文末。
- `可空` 对应物理定义。`—` 表示没有默认值，`NULL` 表示可空列的有效默认值，`自增` 表示 `AUTO_INCREMENT`。
- 软删除列出现在 `t_user`、`t_goods`、`t_favorite`、`t_blacklist`、`t_trade`、`t_evaluate`、`t_feedback`、`chat_message` 和 `t_account_audit_log`。业务查询按各表实现使用 `is_delete=0`，时间列以各表定义为准。
- Token、商品草稿、待确认交易意向和热门推荐缓存由 Redis 管理。成交后才写入 `t_trade`，商品、评价和聊天媒体的文件存储在对象存储，MySQL 保存关联 URL。

## 用户与管理

### t_user

**校园用户**。用户以学号或工号形式的字符串作为 `user_id`。登录后业务通过该 ID 关联发布者、买家和卖家。主键在应用中由登录流程赋值。 排序规则为 `utf8mb4_0900_ai_ci`。 [TUser.java](../src/main/java/com/bit/scmu_taotao/entity/TUser.java)

| 列名 | MySQL 类型 | 可空 | 默认值或生成规则 | 用途 |
| --- | --- | --- | --- | --- |
| `user_id` | `varchar(32)` | 否 | — | 用户主键（教务系统学号/工号） |
| `user_name` | `varchar(50)` | 否 | — | 真实姓名 |
| `avatar` | `varchar(255)` | 是 | `'系统默认头像URL'` | 头像 URL。物理默认值是下列字面字符串，应用登录和用户资料有自己的头像回退逻辑。 |
| `credit_score` | `int` | 否 | `100` | 个人信誉分（初始100分，扣分制） |
| `credit_star` | `decimal(2,1)` | 否 | `5.0` | 信誉星级（0-5星，保留1位小数） |
| `create_time` | `datetime` | 否 | `CURRENT_TIMESTAMP` | 账号创建时间 |
| `update_time` | `datetime` | 否 | `CURRENT_TIMESTAMP`，`ON UPDATE CURRENT_TIMESTAMP` | 信息更新时间 |
| `is_delete` | `tinyint(1)` | 否 | `0` | 软删除标识（0=未删除，1=已删除） |
| `status` | `tinyint` | 否 | `0` | 账号状态。当前代码使用 `0` 正常、`1` 查封、`2` 风险待审核。 |
| `violation_reason` | `varchar(255)` | 是 | `NULL` | 违规原因 |

**索引**

| 索引名 | 约束类型 | 列顺序 |
| --- | --- | --- |
| `PRIMARY` | 主键 | `user_id` |
| `idx_credit_score` | 普通 | `credit_score` |
| `idx_t_user_status_userid` | 普通 | `status`、`user_id` |

## 业务中的关联

| 场景 | 实体或 SQL 使用的关联 |
| --- | --- |
| 账号历史 | `t_user_report.reporter_id`、`t_user_report.target_id`、`t_credit_log.user_id`、`t_account_audit_log.user_id` 对应 `t_user.user_id`。处置总台按有效审核流水的 ID 查询账号最近处置。 |
| 用户会话 | `chat_session.user1_id`、`user2_id` 和 `chat_message.send_id`、`receive_id` 保存参与者标识。消息实际归属受 `chat_message.chat_id` 的外键约束。 |
| 交易与商品 | `t_trade.goods_id` 引用商品。评价通过 `trade_id` 引用交易，同时保留商品和双方 ID。聊天表中另外保留可空的 `trade_id`。 |
| 推荐浏览 | `user_goods_browse.user_id`、`goods_id` 按用户和商品聚合。热门排序和个性化候选查询还读取商品、收藏和图片。 |
